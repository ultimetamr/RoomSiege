# RoomSiege 波次串联

## 2026-10-27 指挥与局内强化

房间和核心在本局锁定。入口显示全波组成/方向/准备倒计时，后续波前 5 秒播放入口方位提醒。所有入口开波都有号角。应急冰冻作用于核心水平 2m 内存活敌人，停止移动 2 秒，冷却 30 秒（只在未暂停战斗时递减）；无目标不消耗。冻结只影响移动，Boss 召唤行为沿用原规则。

第 3、6、9 波清场后弹出强化三选一，选择时战斗和准备倒计时暂停；确认一项后继续 15 秒准备，可重复选择升阶。分别为机枪超频、寒冰连锁与陷阱回收。选择门控保证每个节点只能领奖一次；重开清除强化、冷却、旧塔和旧敌人。教学共六页。

以下为初版模块说明；后续流程与本节冲突时，以本节和 UI 实现为准。

本次实现 Waves/ 的十波调度、准备倒计时、右侧情报与结算，复用 Data/、Scan/、Towers/、Enemies/。按用户要求，未运行测试、编译/构建、模拟器或设备验证。

## 运行流程

- `RoomSiege_Start` 场景自动创建 `WaveController`，等待现有塔配置、敌人池和世界面板初始化。
- 点击已有“开始建造”进入 BUILD，首次开波前和相邻两波之间都有完整 15 秒准备期，可购买、升级、卖出；到时自动进入 WAVE。
- 直接使用 `TowerHost.Catalog.waves` 的现有 W1～W10 配置，不另建一份波次数值。每组均分给最多两个有效入口，通过 `EnemyController.Enqueue` 进入原有 FIFO 队列，沿用 1 秒生成间隔、20 只同屏上限和对象池。
- 以 `EnemyController.IsDrained`（待生成与活跃数量都为零）判断清场。Boss 的活跃/排队召唤物也必须解决。第十波清场且生命大于零后设置胜利并进入 RESULT。
- 生命归零沿用 GameManager 的失败处理并进入 RESULT。失败波的最后一只漏怪也计入统计；结算在 LateUpdate 执行，避开漏血先触发 RESULT、后触发 Leaked 的事件顺序。
- 暂停面板、应用暂停、Time.timeScale 为零时冻结倒计时。扫描中或没有有效入口时等待有效房间，不消耗准备时间。正在进行的波次切换真实房间/沙盘会记一次中断，重新准备同一波，不把清除敌人视为通关；已结算金币保留，中断记录不冒充完成记录。

## 经济、声音与面板

- 初始金币按难度配置为休闲 180、标准 150、硬核 120，使用 `InitializeEconomy` 幂等初始化，准备期不会重置余额。
- 击杀奖励只由 `EnemyController` 加入现有 GameManager 钱包；Waves 的 Killed 订阅仅计数，不重复加钱。不加利息或额外波次奖励。
- 右面板显示准备秒数/当前波、下一波组成、生命、实时金币、本波击杀/漏怪/活跃/待出数量。波后显示该波结算余额和击杀/漏怪数；RESULT 增加总计。
- 顶部已有环显示十波总体进度。号角由 `WaveHorn` 生成短双音 AudioClip，每次开波播放一次，随暂停暂停播放，无需外部音频资源。
- 世界面板原有头部跟随、距离复位及暂停淡化继续由 UI/ 负责。

## 接口与统计口径

`WaveController.Instance` 提供 `IsReady`、`IsPreparing`、`PreparationRemaining`、`IsWaveActive`、`CurrentWave`、`PreviewWave`、`Outcome`、`Results`。

事件：`WaveStarted(int)`、`WaveFinished(WaveResult)`、`CampaignFinished(CampaignOutcome)`、`Changed`。

`WaveResult` 为只读快照，包含波次号、击杀数、漏怪数、结算剩余金币和结算原因（完成/失败/中断）。`Results` 保存本次战役所有波次/中断尝试，不提供持久化。Boss 召唤物正常计入击杀和漏怪，正常按敌人配置奖励金币；主动清除、扫描模式切换时取消的敌人不计击杀或漏怪。

必要接入改动：GameManager 增加当前波次更新和胜利标记，胜负后锁定 RESULT；原“开始建造”及 B 快捷键在 WAVE/RESULT 时不再改变状态；测试桩限准备期手动生成，正式开波会清除已有测试桩，避免干扰真实敌人索敌。没有自动执行任何测试桩或验收流程。
