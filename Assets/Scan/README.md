# RoomSiege Scan

## 2026-11-03 Boss 通路与建造范围

0.8m 圆环仅用于敌人漏怪判定，不再整圈禁止建造。每个入口到核心保留一条可达路径，沿路径按 Boss 体型排除部署格，存入 `ReservedRouteCells`；路线外避开核心本体的 0.16m 水平半径、入口足迹、家具与不受支撑的格子。Boss 身体宽 0.56m，按 0.4m 部署格保留至少 2 格宽通道，拐角或跨格时按整格避让可能更宽。核心移动时同步路线禁放和蓝格显示；已有塔不因核心移动而删除，地面塔仍需通过 Towers 的可达性检查。

## 2026-10-30 真实房间通路恢复

房间三维框未提供有效局部旋转时使用单位旋转，保留已定位的锚点朝向；入口标定和恢复记录均按旋转后的家具盒检查占用。初次读取真实房间时，若脚下核心周围没有可通行节点，在 2m 内寻找最近有效地板并明确提示调整；已有有效核心不移动，整间房不可通行时继续提示调整位置。

标定不仅检查地板与距离，还通过 Towers 提供的 `LayoutFailure` 检查入口到核心及入口两侧通路。失败时保留真实房间和标定状态，不保存无效入口，不再提示可以开局。导航线段逐格检查所有穿过的节点，避免粗略采样漏掉家具边角后敌人在原地踏步。

手动入口检查实际向内 0.65m 的生成点，而不只是点中的地板。该位置被家具或边界阻挡时，在所选点周围最多 0.8m 内寻找最近有效位置，同时验证左右错列通道、后退生成留量与核心通路，成功后提示对齐；无可用位置时继续标定。恢复已保存入口时也执行相同检查，有效入口保持原位，调整后的入口重新保存至地板锚点局部坐标。

## 2026-10-27 固定核心与地面导航

安全区现为固定守护核心周围 0.8m，本局不随头部位置变化。玩家走动不重建格子或移除已购武器。房间准备页“核心设在脚下”可在开局前主动重设；进入战役后锁定房间和入口，自动空间刷新结果不会在战斗中重排部署格，返回菜单后可重扫。

`GridModel.WalkMap` 保存独立地面导航网格（0.2m），包含安全区和入口附近区域，与排除了禁放区域的 0.4m 部署格分开。家具和地板边界按最大敌人体型保守避让；Towers 在该图上叠加普通地面塔阻挡并检查可达性。真实房间不可达时，准备页会禁用进入建造并提示调整核心或使用沙盘。


仅实现房间输入、网格数据、扫描预览和模拟沙盘。不包含塔、敌人、波次、寻路或战斗。

## 使用

打开 `RoomSiege_Start` 场景。ScanController 在该场景运行时自动创建；Android 已有空间数据权限时自动恢复已扫描的真实房间，等待 OpenXR 就绪后读取，并在读取结束时重新检查透视能力。首页统一为“开始游戏”；复用已定位房间或后台读取系统已有数据，只有主动点“重新扫描真实房间”才打开系统房间采集。扫描完成后自动准备可达入口，不要求手动标定；空间不足时自动回退沙盘。权限和系统确认由用户选择。

2026-11-04 更新：“开始游戏”通过 `BeginGameRoomScan` 重新读取已保存房间，并展示房间准备 1/8～8/8（透视、锚点、地板边界、部署格、核心、入口、Boss 通路、就绪）。读取完成前禁止进入建造，每步最少可见 350ms。这个计数表示应用准备阶段；底层地板最多八次查询重试另行描述，不能当作八个实际采集点。`UseRealRoom` 保留为复用已准备场地的内部入口。

世界空间面板提供：

- **真实扫描**：开启 PICO Passthrough，查询房间语义锚点。没有房间数据时启动系统 Room Capture。系统权限和确认由用户选择。
- **模拟沙盘**：取消当前请求，生成以玩家为中心的 6×6m 虚拟客厅（地板、桌、矮柜、沙发和 1 个入口）。
- **虚拟格叠加**：切换格线和核心本体占用辅助线；核心圆环与出怪口标记继续显示。
- **标定入口**：按按钮开启标定，用任一手柄或手势射线指向门洞/过道地板，再扣扳机或捏合确认。使用与 UI 相同的已追踪射线，点 UI 不会同时标定地板，开启标定的那次点击必须先松开。标定点须在地板内、8m 以内且距核心至少 1.8m，且不能被家具占用。无效目标保留标定状态；也可再次按按钮取消。手动入口优先，最多保留 2 个入口。

真实房间手动入口存入 PlayerPrefs，坐标以对应地板语义锚点的局部空间保存；下次读取同一锚点时随其定位恢复，不能把旧世界坐标直接套到新房间。锚点不匹配、入口落在新边界外、靠核心太近或被家具占用时忽略保存值，仍提示标定。沙盘不写入真实房间记录。

Unity/能够向应用透传键盘的环境也支持 R（真实）、S（沙盘）、G（格叠加）、C（直接按视线标定）。PICO 模拟器会占用部分键盘快捷键；Android 验收以面板和控制器射线操作为准。

## 数据契约

命名空间：`RoomSiege.Scan`；程序集：`RoomSiege.Scan`。

```csharp
var scan = ScanController.Instance;
var grid = scan.CurrentGrid;
if (grid != null)
{
    foreach (var cell in grid.PlaceableCells)
    {
        Vector3 worldPosition = cell.Center;
        string supportAnchor = cell.SurfaceId;
    }
    var entrances = grid.SpawnPoints;
    Vector3 safeCenter = grid.SafeZoneCenter;
}
scan.GridChanged += HandleGridChanged; // 使用方负责在销毁时退订
```

`GridChanged` 的处理器签名为 `void HandleGridChanged(GridModel model)`；真实扫描开始时会发布 null，调用方必须处理暂时无模型的情况。数据更新后发布新快照，不修改已发布的 GridModel。列表为只读副本。

- 所有坐标为 Unity 世界坐标，单位为米；Y 为高度，XZ 为地板投影。
- `PlaceableCells` 含完整通过检查的格子：世界中心、表面类型、表面锚点 ID、世界 XZ 格索引。格索引相同的不同高度表面可分别存在。
- `SpawnPoints` 含锚点 ID、世界位置、朝室内的水平方向、禁放足迹大小及手动标定标志。
- `SafeZoneCenter` 为玩家当前 XZ 投影到地板；`Mode` 是实际数据来源（RealRoom 或 Sandbox），`RequestedMode` 表示最近请求的模式。因此扫描失败时 RequestedMode 可为 RealRoom，CurrentGrid.Mode 为 Sandbox。
- 网格边长 0.4m；漏怪圆环半径 0.8m，不禁止建造。只按整格最近边缘排除核心本体 0.16m，地板与家具顶面统一检查。
- 整格须落在部署面内，避开入口足迹和家具占用。家具边界额外保守扩展 5mm。桌/柜支撑体不阻挡其自身顶面。
- 玩家移动超过 2cm 时更新安全区（最多每 0.1s 检查一次）。真实模式每 5s 或房间数据事件后重新定位语义锚点。

## MR 适配

基于项目已安装的 PICO Unity SDK 6.1.1 源码，使用 OpenXR PassthroughFeature、PICOSceneCapture、PICOSpatialAnchor，以及 PXR_MixedReality 的 Scene Capture 查询和定位 API。

房间结构由**房间语义锚点的地板多边形、门/Opening 二维框、家具三维包围盒**重建；没有把单独的空间锚点假设成完整房间网格，也不生成实时三角网格扫描。门洞/过道依赖系统 Door/Opening 语义标签，不能保证识别未标注的通道。

桌/柜顶面要求近似水平（法线与上方向点积 > 0.97），离地 0.25–1.2m；过高柜体只作为障碍。原生地板允许最多 3 度姿态倾斜并统一到水平高度，不按房间整体高度跨度拒绝宽房间；桌柜部署面仍要求顶面高度差不超过 5cm。门洞须宽至少 0.5m、高至少 1.2m。

无原生能力、权限/数据查询失败、显式系统采集超过 180s、启动后台查询超过 45s、房间更新超过 15s、地板面积不足 6m²或可放格不足 8 个时回退沙盘。优先复用可达的门洞或已保存入口；没有 Door/Opening 或原入口不可达时，在真实房间内自动布置虚拟出怪口，按核心连通区域、至少 1.8m 距离、家具避让、生成点两侧留量与实际通路检查后保存到地板锚点。不能自动取得可玩布局时回退沙盘，不把手动标定作为开局前置条件。准备页可选“调整出怪口”。界面显示实际模式和失败原因；模式切换取消旧请求，迟到结果不会覆盖新模式。

开启的 Android OpenXR 功能：Passthrough、Scene Capture、Spatial Anchor。SDK 构建处理器根据功能添加空间数据权限。真实扫描与沙盘均使用现实透视；相机 SolidColor、透明背景 alpha 0、关闭 HDR。应用恢复焦点后重新确认 SDK 透视开关并恢复透明相机；SDK 扩展尚未就绪时延后重试。首页对决背景图只在 MENU 显示，不覆盖扫描或战场。

## 构建与测试

真实房间导航按家具旋转后的世界高度和 XZ 凸包计算避障，不把原生包围盒局部 Y 轴当作世界竖直轴。世界最低点高于地板 0.55m 的悬空物件不会阻断地面导航；实际落地家具继续保留敌人体积留量。首次核心恢复忽略少于 32 个导航节点的孤立碎片，在 2m 内选择最近连通区域，有效核心保持原位；没有附近区域时继续报告失败。

Unity 菜单 `RoomSiege > Scan`：

- `Configure MR Features`：配置功能与相机。
- `Build Scan APK`：输出 `Builds/RoomSiege-Scan.apk`，结果写入 `Builds/scan-build-result.txt`。
- `Run EditMode Tests`：执行 Scan 测试，输出 `TestResults/RoomSiege.Scan.EditMode.xml`。

2026-10-26 验证：EditMode 14/14；Android 构建成功、错误 0；PICO Emulator 0.13.0 运行沙盘输出 89 格、1 入口、安全中心 (0,0,0)。日志记录真实扫描请求后的 Sandbox 回退，以及 Overlay False/True。模拟器不等同于真实房间采集验证；真实透视、语义锚点定位和系统房间扫描效果须在支持功能的 PICO 真机上验收。
